# Что пересмотреть при обновлении Qt и Quickshell

Не разбор бага, а список мест, где код написан **под поведение конкретной
версии**. При смене Qt или Quickshell их стоит перепроверить: часть можно
будет упростить, часть — наоборот, нельзя трогать, и здесь написано почему.

Каждый пункт содержит способ проверить состояние за одну команду, чтобы не
полагаться на память.

## Версии на момент написания (24.09.2026)

| Что | Версия |
|---|---|
| Qt, против которого слинкован quickshell | **6.9.3** (`ldd ~/.local/bin/quickshell-bin`) |
| Qt, установленные в системе | 6.8.3 и 6.9.3 (`~/.local/opt/Qt/`), используется только 6.9.3 |
| Quickshell | **0.3.1**, ревизия `c6a51609` |

## 1. `SettingsSearchAnchor.qml` — НЕ упрощать обратно

**Файл:** `Widgets/common/SettingsSearchAnchor.qml`
**Что там:** подсветка найденной секции не парентится в цель напрямую, а
выбирает хост (`highlightHost`) и считает координаты через `mapToItem`
(`highlightArea`).

**Почему так.** `QtQuick.Layouts` управляет всеми видимыми детьми: anchors в
них не работают, а видимый элемент занимает отдельную ячейку и раздвигает
содержимое. Часть целей — обычные `Rectangle` (`SettingsSection`,
`MaterialCard`), часть — `ColumnLayout` (`KeystoneSection`, компоненты
`Section` в `ThemePage` и `WallpaperPage`), 18 использований из 61. Простой
вариант `parent: target; anchors.fill: parent` давал **394 предупреждения в
логе за сессию** и ломал раскладку этих страниц во время подсветки.

**Про `Layout.ignore` — его не существует.** Ни в 6.9.3, ни в 6.11.2 (самая
свежая документированная на момент написания). Это не «ещё не завезли, потом
вернём» — такого свойства в Qt Quick Layouts нет вообще, и в документации
`Layout` его никогда не было. Документированные способы исключить ребёнка из
раскладки ровно три: `visible: false`, **перепарентить наружу** и
`LayoutItemProxy` (Qt 6.6+, решает обратную задачу — один элемент в
нескольких раскладках).

То есть текущее решение — второй из документированных способов, а не обход
чего-то временного. **Упрощать обратно нечего и не нужно ни в какой версии.**

**Как перепроверить, если всё-таки понадобится:**

```bash
cat > /tmp/probe.qml <<'QML'
import QtQuick
import QtQuick.Layouts
import Quickshell
ShellRoot {
    Component.onCompleted: {
        const p = Qt.createQmlObject('import QtQuick; import QtQuick.Layouts; Item { Layout.ignore: true }', this, "probe");
        console.log("Layout.ignore существует:", p !== null);
        Qt.quit();
    }
}
QML
qs -p /tmp/probe.qml; rm /tmp/probe.qml
```

На 6.9.3 печатает `Cannot assign to non-existent property "ignore"` (проверено).
Файл нужен настоящий: через `/dev/stdin` не работает, Quickshell берёт корень
модулей `qs.*` из каталога переданного файла.

## 2. `WheelScrollController.qml` — `Connections` вместо обработчиков свойств

**Файл:** `Widgets/common/WheelScrollController.qml`, около строки 132
**Что там:** состояние `Flickable` наблюдается через `readonly property` +
`onXxxChanged`, а не через `Connections`.

**Почему так.** Комментарий в файле: в **Qt 6.11.2** асинхронное создание
страницы падало в `connectSignalsToMethods()` на нулевом JS-методе.
Обработчики свойств этот путь инициализации не задействуют.

**Что пересмотреть.** Это единственная запись в проекте, привязанная к
конкретной версии Qt и к **более новой**, чем текущая 6.9.3. Если будете
переходить на 6.11.x или новее — проверьте, починен ли краш; если да, блок
`observedContentX/Y/Dragging/Interactive` можно свернуть обратно в один
`Connections` и убрать четыре лишних свойства.

**Как проверить:** открыть любую страницу настроек, которая создаётся
асинхронно (`Loader { asynchronous: true }`), несколько раз подряд. Краш был
при создании, не при работе.

## 3. `WheelScrollController.qml` — контроллер съедает все события колеса

**Файл:** тот же, `handleWheel()`
**Что там:** `event.accepted = true` выставляется сразу и не снимается — ни
на нулевых событиях границ жеста, ни на упоре в край.

**Почему так.** Разбор в `bug_4_прокрутка_прыгает_на_краю_списка.md`. Кратко:
отданное событие достаётся не «внешнему списку», а самому `Flickable`, и тот
доигрывает жест от своего устаревшего якоря, швыряя список в позицию из
прошлого жеста.

**Что пересмотрели бы.** Это не обход версии, а следствие того, что
`Flickable` забирает колесо безусловно. Если в будущем Qt научится
пробрасывать колесо дальше при упоре (настоящее scroll chaining) — можно
будет вернуть передачу наружу и получить «внутренний список кончился,
докручиваем страницу». Сейчас этот сценарий не работает **в принципе**, так
что ничего не потеряно.

**Как проверить:** стенд из `bug_4`, раздел «Проверка». Признак поломки —
`drag=true` у `Flickable` при упоре.

## 4. `MaterialSymbol.qml` — квантование `opsz` и `FILL`

**Файл:** `Components/MaterialSymbol.qml`
**Что там:** `renderedIconSize` округляется до целого, `opticalSize`
загоняется в четыре значения (20/24/40/48), `fill` — до одного знака.

**Почему так.** Qt создаёт отдельный `QFreetypeFace` на каждую уникальную
комбинацию `variableAxes`, и каждый заново отображает файл шрифта. Замер на
текущей сборке: **10 новых значений `FILL` = +5.5 МБ RSS**, то есть ~0.55 МБ
на вариацию; в живой оболочке шрифт значков был отображён **35 раз** (16.9 МБ
резидентно при файле 988 КБ). До урезания шрифта (см. `bug_1`) файл весил
10.6 МБ, и те же 35 вариаций стоили бы порядка 370 МБ.

**Что пересмотреть.** Если Qt начнёт переиспользовать `QFreetypeFace` между
осями — квантование можно ослабить и анимировать `fill` плавно.

**Как проверить:**

```bash
grep -c "material-symbols-rounded" /proc/$(pgrep -x quickshell-bin)/maps
```

Сейчас это число ≈ количеству живых комбинаций осей (по 2 отображения на
комбинацию). Если после обновления Qt оно упадёт до 1–2 при неизменном UI —
ограничение снято.

## 5. `DockerWidget.qml` — у `Process` нет `failedToStart`

**Файл:** `Modules/Keystone/DeveloperContent/DockerWidget.qml`, около строки 40
**Что там:** отсутствие `docker` в `PATH` определяется идиомой «never
started» — через `onRunningChanged` и флаг `_dockerStarted`, а не сигналом.

**Почему так.** В **Quickshell 0.3.1** у `Process` сигнала `failedToStart`
нет. Тот же приём используется в `NetworkManagerExtras`.

**Что пересмотреть.** Если Quickshell добавит `failedToStart` — оба места
можно упростить и заодно перестать путать «не запустился» с «запустился и
сразу упал».

**Как проверить:** в сообщении Quickshell при отсутствии бинарника уже есть
нужный текст (`Process failed to start, likely because the binary could not be
found`) — значит, событие внутри есть; вопрос только в том, выставлено ли оно
в QML API. Смотреть в документации `Quickshell.Io.Process` на предмет
`failedToStart` или аналога.

## Чего в этом списке нет

Эти правки от версий **не зависят**, пересматривать их при обновлении не надо:

- `boundsBehavior: StopAtBounds` в `StyledListView`/`StyledFlickable`/
  `StyledGridView` — осознанный выбор поведения, а не обход.
- `Timer { interval: 0 }` вместо `Qt.callLater` в `Tray.qml` — исправление
  висячего отложенного вызова; `Qt.callLater` переживает объект по замыслу, и
  это не изменится.
- Возвраты `NaN` вместо `undefined` в `SysMonitor.qml` и `!!` в
  `DisplayAdvancedSettings.qml` — типы QML, а не версии.
