# Bug 3. Контейнеры Docker «прыгают друг на друга» при нажатии hide/show

Симптом: вкладка Developer, виджет Docker. После нажатия на чип `hide` (или
`show`) у compose-группы оставшиеся строки на кадр-два наезжают друг на
друга, список дёргается, а потом щёлкает в нормальную раскладку.

## 1. Причина бага

Причин было две, и они складывались. Первая итерация фикса закрыла только
одну — баг выжил, поэтому ниже описаны обе.

### 1.1. Пересбор модели на каждое сворачивание

`toggleCollapsed()` дёргал `applyPsRows()`, а состав строк зависел от
`collapsedProjects`: у свёрнутой группы набор ключей модели другой, и старый
код шёл по ветке «изменился набор или порядок» — **`rowsModel.clear()` +
`append()` по всем строкам**. Разом уничтожались и пересоздавались вообще
все делегаты списка, включая те, что не менялись.

### 1.2. Высота делегата зависела от `implicitHeight` вложенного Layout

```qml
height: Appearance.spacing.small
        + (kind === "group" ? groupHeader.implicitHeight : containerRow.implicitHeight)
```

У свежесозданного делегата `implicitHeight` дочернего `RowLayout` известен
не сразу, а после первого прохода QtQuick.Layouts. ListView расставляет
новые делегаты по тем высотам, что есть на этот момент, и пересчитывает
позиции, когда `implicitHeight` дозреет. Промежуточный кадр — это и есть
«контейнеры наехали друг на друга». Анимаций смещения нет
(`animateMovement: false` в `StyledListView`), поэтому скачок ничем не
сглажен.

При обычном тике опроса (`Up 38 → Up 39 minutes`) набор ключей не менялся,
делегаты не пересоздавались и всё было ровно — совпадает с симптомом
«дёргается только на hide/show».

### 1.3. Почему первой правки не хватило

Первая итерация перевела `applyPsRows()` на инкрементальный diff по ключам
(см. 2.1) — пересоздание «всех делегатов разом» ушло. Но строки свёрнутой
группы по-прежнему **удалялись из модели**, а при `show` — вставлялись
обратно. Любая вставка создаёт новые делегаты, а у них по-прежнему
действовал п. 1.2. Наложение осталось, просто на меньшем числе строк.

## 2. Решение

Всё в `Modules/Keystone/DeveloperContent/DockerWidget.qml`.

### 2.1. Инкрементальная синхронизация модели (из первой итерации, оставлена)

Вместо `clear()+append()` — три прохода по ключам:

1. **remove** — снять только строки, которых нет в целевом списке (справа
   налево, чтобы индексы не съезжали).
2. **на месте / move / insert** — проход по `desired`: ключ совпал —
   `set()` только при реальном отличии; строка есть ниже в модели —
   `move()` на нужную позицию; нет — `insert()`/`append()`.
3. Страховка — снять хвост, если он длиннее целевого списка.

Это нужно само по себе: тик опроса раз в 4 с не должен пересоздавать
делегаты ради `Up 38 → 39 minutes`.

### 2.2. Высота строки — константа по типу (ключевое)

Введены `groupRowHeight` / `containerRowHeight` (и `groupContentHeight` /
`containerContentHeight` для содержимого). Теперь **высота известна в
момент создания делегата**, а содержимое привязано якорями внутрь этой
высоты, а не наоборот. Кадра со старой/нулевой раскладкой физически не
остаётся.

### 2.3. Сворачивание вообще не трогает модель

Контейнеры свёрнутых групп остаются в `rowsModel`: `applyPsRows()` больше
не зависит от `collapsedProjects`, а `toggleCollapsed()` не вызывает
пересбор. Скрытие живёт в делегате:

```qml
readonly property bool rowHidden: !isGroup && collapsedNow
height: rowHidden ? 0 : (isGroup ? root.groupRowHeight : root.containerRowHeight)
opacity: rowHidden ? 0 : 1
clip: true
enabled: !rowHidden
```

`clip` режет содержимое при схлопывании и заодно отсекает клики по кнопкам
скрытых строк. Роль `collapsedNow` из модели убрана — делегат читает
`root.isCollapsed(projectKey)` напрямую (переприсваивание
`collapsedProjects` целиком пересчитывает биндинг).

При hide/show делегаты теперь не создаются и не уничтожаются — меняется
только их высота. Наложения не бывает в принципе.

### 2.4. Плавность

`Behavior on height` + `Behavior on opacity` (`Animations.durations.small`,
кривая `standard`): группа складывается и раскрывается аккордеоном, строки
ниже подтягиваются одной анимацией, а не скачком.

## 3. Краткая информация (сделано)

**Сделано.** Изменён один файл —
`Modules/Keystone/DeveloperContent/DockerWidget.qml` (плюс актуализированы
комментарии в шапке файла, они описывали старую механику высот).

**Проверка.**

- Живой quickshell перечитал конфиг: `Configuration Loaded`, ошибок нет.
  Но одного этого **мало**: вкладка Developer ленивая
  (`active: currentIndex === 3 || loadedOnce` в `Hub/HubContent.qml`), в
  логе за всю сессию не было ни одной строки про Docker — значит виджет ни
  разу не инстанцировался, и «конфиг загрузился» доказывало только
  компиляцию, а не живость биндингов делегата.
- Поэтому виджет поднят отдельным временным инстансом
  (`qs -p <FloatingWindow с DockerWidget>`) на реальных данных — подхватились
  compose-проекты `docker` и `infra`:
  - прогон 1: collapse всех групп → expand — лог чистый;
  - прогон 2: 16 с автотыканья hide/show каждые 700 мс (быстрее 200 мс
    анимации и внахлёст с 4-секундным `docker ps`) — **ни одного
    предупреждения**.
  - Проверялось в том числе отсутствие `Required property was not
    initialized` (главный риск после удаления роли `collapsedNow` из
    модели) и `QQuickItemView: possible infinite loop` от строк нулевой
    высоты. Временный харнесс удалён.
- `qmllint` на этой машине не применялся: локальная версия не понимает
  `pragma ComponentBehavior: Bound` и падает на первой строке.
- В git ничего не коммитилось и не пушилось.

**Проверка в UI (за пользователем).** Вкладка Developer → `hide` у группы,
затем `show`: строки должны плавно схлопываться и раскрываться аккордеоном,
без наложения и без скачка; скролл остаётся на месте.
